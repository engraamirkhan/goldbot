- Multi-instrument demo, lane L3 (engine), ADR 0074: one engine per account, one SymbolBook per instrument (`goldbot/engine/books.py`). Engine attributes that belong to one instrument (bars, resamplers, ticks, cost and contract caches, open trades and order rows, exploration, session table, magic range, journal) are data descriptors on the active book; the RiskGate, the one AccountState, the kill switch, risk-period state, approvals and order sender stay the account's. The run loop takes the books in turn on one thread (`books.account_pass`, quotes batched by `QuoteFeed`/`ticks_many`), so the gate is serial; each book keeps its own copy of the instrument facts the gate reads (spread, quote age, staleness, market hours, blackout, Friday cut). Trading-safety E1-E7 (#307 review): the check runs on the one canonical state; an entry is booked (`RiskGate.book`) right after its order went out and entries wait until a refresh sees the fill; the session profile narrows entries only (exits and bars read the broker's hours); `group_notional` (deposit currency), `open_lots`/`open_notional` (gold group) and `other_group_notional` are set every refresh, and `group_notional` is published null when exposure is unknown; an intent whose `symbol` is not the book's instrument is refused (`symbol_mismatch`); each symbol's Friday cut runs at its profile's time; live and pilot accounts stay XAUUSD-only. An entry that would take the account past the bridge's 6x equity ceiling is refused first (`account_notional_cap`). XAUUSD is the primary book built from EngineConfig as before: the four-day replay is pinned to main (`tests/test_mi_xauusd_replay_golden.py`); the engine-store golden gained only `symbol` on open trades (gold's orders file is unchanged). Safety fixes: every price sent (stop, target, trail, orphan stop, BXR trail, pyramid stop) is rounded to the instrument's digits; an unknown contract size refuses entries (`contract_unknown`), never 100 oz. Lane L1's scheme: books take `accounts.instrument_magic_base`, run only their own registered `S0-<key>`/`I0-<key>` controls (now `status: run`, registered on icm-probe and vantage-demo; host pins updated), stamp `ExplorationRecord.symbol`, `OpenTrade.symbol` and `ClosedTrade.symbol` with the instrument key, pass `{"symbol": key}` to feature builds and refuse every entry on a spec with `verify: true` (`instrument_unverified`); its exits run. Non-gold rows go to the store as (source=account, symbol=store_symbol) and order rows to `state/books/<account>/orders_<store>.json`; lot and swap terms per (account, symbol) live in `state/instruments.db` (SQLite WAL); unreadable or missing terms, an unconvertible swap or no `max_spread_points` refuse that book's entries while its exits run. engine_<account>.json gains `books`, `symbols`, `groups`, `heat_used`/`heat_limit` and `group_notional` (lane L4's contract). Key levels (#306 follow-ups): the pull lock keys on the account's `box` or the tunnel port behind a loopback URL, and a hole the broker has no bars for is not re-read before HEAD_RECHECK. runner.py moves: the closed-trade record to `engine/closed_record.py`.
