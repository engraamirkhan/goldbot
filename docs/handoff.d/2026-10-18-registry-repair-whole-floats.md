- **Research cells: whole floats no longer fail a trial; registry repair** (readout 2026-10-18, D-1; ADR 0033): GitHub's matrix writes 3.0 as 3, so the planned agent id differed from the cell's and `record` wrote `failed` rows for 12 cells that ran (#21-28, #30-32, #35). `cells.plan` now emits `canonical` variants (whole floats as ints, the matrix's own form) and `_planned` canonicalises old plans; a cell row may not carry `repair`. `scripts/registry_repair.py REGISTRY RUN_DIR...` (dry run; `--apply`) puts each cell's row in its failed row's place, same timestamp, trial number and K, with `repair.replaces` and provenance (`run_id` checked by `gh run view`, `head_sha`, `rows_sha256`); `registry_sync.merge_rows` drops a failed row a repair names only in its own slot (same ts and trial number), so a stale copy (the VPS) cannot bring it back. Publishing needs quant-reviewer approval first. A one-cell run no longer loses its rows: download-artifact extracts a lone artifact into `cells/` itself, which `record` now reads for a one-cell plan (`cells.cell_dir`; B08 #44).
