# Trades experience: audit and redesign spec (2026-10-27)

Owner request (2026-10-27): "review and analyse trades ui/ux design, it should show information that is valuable and
complete". Author: principal product designer. Status: **reviewed; quant-reviewer tightenings folded in (§2.5, 2026-10-27)**;
web build in progress. Decision record: ADR 0050 (money always visible, arm results blinded until their read). Backlog: items
128-134. Follows `docs/ux/design-system.md` (tokens, components, rules 1-6) and keeps the binding blinding rule of
`docs/ux/daily-learning-report.md` §3.4.

Scale this must be right for: ~50 exploration arms (~30 families, timeframes as variants) on 3 demo accounts heading
for about 200 fills a day per account (500+ a day overall), plus cost probes, shadow models and, later, real-money entries the owner
confirms in 90 s. The owner is a trader on a phone first, a Mac second; he thinks in **strategies** (a family across
timeframes), and wants to see learning progress and money without asking.

---

## 0. The short version

The trades screens were built for a handful of engine trades a day. At 500+ fills a day they fail in five ways:

1. **Money is "not known" on every open row** (dashboard "money not known", CLI "risk ? GBP pnl ? GBP"). Root cause
   found: the engine never writes `usd_to_account` into `engine_<account>.json`, and every account is GBP, so
   `account_view.usd_to_account()` returns None and both floating P&L and open risk are None. The engine already has
   the rate (`Engine._open_fx`, `_open_risk_rows`); it just isn't published.
2. **Exploration trades, 95%+ of all fills, are invisible to the dashboard.** Activity and Trades summary read shadow,
   orders files, closed_trades and `cost_probes`; none reads aux.db `exploration_trades`. Only open arm positions
   appear (via the orders file). The Telegram digest had the same bug and was fixed (D1); the dashboard was not.
3. **Activity cannot work at volume.** 200 events, newest first, no filter, open and close as two rows, raw ids
   (`ex:BXR-5m`, `tsmom-g0`), "SL/TP" jargon. At 500+ fills/day (two events each) 200 events is about 4 hours; the owner can neither find a
   trade nor see a strategy.
4. **There is no strategy view.** Nothing groups a family across timeframes, shows progress toward its read, its
   annealing state, its budget, or its verdict against its control. The owner's main question, "is it learning, and
   what has it learned?", has no screen.
5. **The open-trade row misses the essentials.** No account on the row (two accounts mixed in one list), no risk in £,
   no time held, no costs, no reason, no exit plan in words; timeframe printed twice ("BXR-5m 5m"); "probe" means both
   a cost probe and an exploration arm.

The redesign: **Trades = Now / List / Strategies / Today**, one trade-ledger API with server-side blinding, money on
every row, a trade detail with a small SVG chart, and a Telegram policy of "push real money and safety, pull the rest".

## 2. Information model

Three objects, one vocabulary. Every field below is either already stored (source named) or is a new field for the
API (marked **new**). Units: prices USD/oz 2 dp; money in the account currency (GBP today) with sign and true minus;
R = result over the risk at entry; times UTC in the API, owner local on screen with UTC on hover.

### 2.1 Kinds (one word each; replaces the overloaded "probe")

| Kind | Meaning | Source |
|---|---|---|
| **Real** | owner-confirmed, real-money entry | orders + closed_trades, mode live |
| **Strategy** | an engine strategy's demo entry (auto, ADR 0036) | orders + closed_trades, mode demo |
| **Exploration** | an arm's minimum-lot learning trade | aux `exploration_trades` |
| **Control** | an exploration arm whose rule is `random_bracket` (S0, S0R, I0, W0, VI0, VW0) | `ExplorationRecord` + `labs.control_arm_ids()` |
| **Cost probe** | P0 cost measurement order | aux `cost_probes` |
| **Shadow** | paper trade, no order | `shadow_book.json` |

### 2.2 Per trade (`TradeRow`, **new**, served by `GET /api/trades` and `GET /api/trades/{trade_id}`)

| Field | Type | Source / rule |
|---|---|---|
| `trade_id` | str | stable: `<kind>:<account>:<client_order_id or position_id>`; shadow `shadow:<agent>:<entry_ts>` |
| `kind` | enum §2.1 | derived |
| `account_label` | str | `labs.ROLE` ("Scalp lab", "Day/swing lab", "Vantage lab", "Live (ICM)"); never the slug |
| `mode` | demo/live/paper | engine file |
| `family`, `family_label` | str | `family_of`; label from a **new** `config/strategy_labels.yaml` ("Box break + close", "Opening range", "Random control (scalp)") |
| `variant` | str | timeframe, plus a variant tag when an arm has two rules on one tf (e.g. "5m runner") |
| `timeframe` | str | record |
| `arm_id` | str or null | exploration only; shown under "Details" |
| `is_control` | bool | §2.1 |
| `side`, `lots` | | record |
| `entry`, `stop`, `target` | float | fill price; stop/target at entry (`initial_sl` / `stop_usd`, `target_usd` from fill) |
| `stop_now` | float or null | the engine's current stop when moved (trail, break-even) |
| `exit`, `exit_utc`, `exit_reason` | | `target`, `stop`, `time`, `trail`, `friday_cut`, `kill_switch`, `manual`, `other` |
| `censored` | bool | exploration: closed by anything but its own barrier |
| `opened_utc`, `held_s`, `hold_limit_s` | | `hold_s` (arms) or `max_bars x tf` |
| `risk_amount` | float £ | loss at the stop at entry: `stop_loss` (arms), gate sizing (engine), `open_risk` basis |
| `pnl_now` / `pnl` | float £ | open: mid-price mark (needs 128); closed: broker net |
| `r_now` / `r` | float | over `risk_amount` (arms: `pnl / stop_loss`) |
| `costs` | {spread, slippage, commission, swap} £ | labs' cost rules; `costs_total` and `costs_r` |
| `why` | str ≤ 80 chars | arm: the rule in words from the frozen spec ("Close above the 15m box after a squeeze"); engine: top 2 features in plain words + p; shadow: "below threshold, not taken" etc. |
| `blinded` | bool | true when this row's result fields were withheld (ADR 0050, §2.5) |
| `evidence` | enum | `counted` (admissible toward the read), `excluded` (quarantine/exclusion list, with `excluded_reason`), `censored`, `not_evidence` (probe, real) |
| `price_now`, `as_of`, `stale` | | engine file |

### 2.3 Per strategy (`StrategyBoardRow`, **new**, `GET /api/strategies/board`)

One row per family; variants (timeframes) nested.

| Field | Before the arm's read | After the read |
|---|---|---|
| `family_label`, `style` (scalp/intraday/swing), `accounts` | yes | yes |
| `variants[]`: `timeframe`, `arm_id`, `is_control` | yes | yes |
| `n_counted`, `n_read_at` (300), `fills_today`, `fills_7d` | yes | yes |
| `eta_read_date` | yes: from the 7-day fill pace, "about Thu 5 Nov" | — |
| `band` | running / retired at its stop. "Near its stop" is never shown before the stop has fired (quant review, §2.5): a running arm reads "running" whatever its loss | — |
| `anneal_state` | E exploring / C1 candidate / P proven / R retired (volume-500 plan §4) | same |
| `budget_used_today` | lab-level only (per-arm share is banned, D3) | per arm allowed after P |
| `open_now` | count | count |
| `verdict` | — | `read_verdict` text |
| `net_r_per_trade`, `ci90`, `hit_rate`, `vs_control_r`, `net_gbp` | **withheld (never in the payload)** | yes, frozen at the read sample; live figures after the read are labelled "since read" |

Engine strategies and shadow models are not pre-registered arms: their rows carry the full figures (as Trades summary
does today), with n and a 90% CI always beside an average (no mean R without n).

### 2.4 Per account (`TodayAccount` extended, **new fields** on `GET /api/today`)

| Field | Meaning |
|---|---|
| `fills_today`, `fills_target` (the plan's per-account target from config, about 200 per lab today; null for live) | count, never hard-coded; `pace` = projected fills by day end from the last 2 h |
| `by_kind`: {kind: {fills, closed, net_pnl, costs, net_r}} | never summed across kinds on screen except the account's day P&L, which the broker gives |
| `open_n`, `open_risk` £ | requires 128 |
| `day_cap_used`, `week_cap_used` (£ and %) | engine `daily_loss_*`, weekly from `week_start_equity` and limits |
| `exploration_pot_used` £ of pot | engine's exploration budget (`budget_share x day limit`) |
| `paused` (−8%), `halted` | existing state, words |

### 2.5 Blinding (ADR 0050, binding; quant-reviewer to confirm before build)

- Money is never withheld from the owner: account P&L, open trades' risk and P&L, any single trade's own result in its
  detail view, lab and style totals (≥3 arms, `MIN_ARMS_FOR_TOTAL`).
- An unread arm's **aggregates** are never computed for the client: no per-arm sum, mean, hit rate, rank, share,
  ahead/behind, or comparison with its control. The API omits the fields (the client cannot leak what it never got).
- The list filtered to **one unread arm** (or any set holding fewer than 3 unread arms, a partly-read family included) returns rows with
  `blinded: true` and result fields null; the screen says "Results hidden until this arm's read at 300 trades (212 so
  far). Single trades: open one to see it." Sorting by result is disabled in any view that contains unread arms.
- After the read: the verdict and the frozen read figures; anything after is labelled "since read".
- **Quant-reviewer tightenings (binding, 2026-10-27):**
  1. **Fewer than 3 unread arms in a set means blind.** Any filter, totals line or lab/style total whose set contains
     unread arms is blinded (count, costs and n only; no net £, R or hit rate) unless it spans at least 3 unread arms
     (`MIN_ARMS_FOR_TOTAL`). This includes a **partly-read family**: a family with one read and one unread timeframe
     holds 1 unread arm, so its filter is blinded, even though its read variant's frozen figures stay visible on the
     board. Rows in a blinded set carry `blinded: true` and null result fields; the totals line says
     "Results hidden: this view holds 2 unread arms (fewer than 3)."
  2. **"Near its stop" only once fired.** The band derived from a running loss is itself a sign of the arm's result.
     Before the read the board shows "running" or "retired at its stop" only; never "near its stop".
  3. **Leak test covers a partly-read family.** The seeded payload leak test (129, 132) includes a filter on a family
     with one read and one unread variant, and asserts the unread variant's seeded R and share appear in no
     `/api/trades*` or `/api/strategies/board` response, rows or totals.

## 3. Screens and flows

Navigation: Trades keeps its place in the bottom bar. Its tabs become **Now · List · Strategies · Today**
(`#/trades/now|list|strategies|today`; old `#/trades/open|activity|summary` redirect). Deep links from Telegram open a
tab and, for a trade, `#/trades/list/<trade_id>`.

Figures in the sketches are illustrative, not measured.

Live updates: every live number sits in a fixed-width tabular-nums box; rows are fixed height (phone 72 px, desktop
40 px); new rows insert above the viewport only when the list is scrolled to the top, otherwise a "12 new · show"
pill appears (no jump). Polls: Now 5 s, List 15 s, Strategies 60 s, Today 15 s.

  line 3 entry → current stop, time held (or "4 of 10 min" against the hold). Kind badge only when not Strategy.
- Desktop ≥ 1024 px: a table with columns Account · Strategy · TF · Side · Lots · Entry · Stop · Target · Risk £ ·
  P&L £ · R · Held · Kind; header sorts; row click opens the detail in a right-hand panel (480 px), list stays.

| State | Shows |
|---|---|

| Empty | "No open trades. The labs open trades on their own signals; the next one shows here." + market state ("Market closed until Sun 23:00") |

| Partly unreadable | amber line "Couldn't read the Vantage lab's trades: missing, not zero"; others shown; totals say "excl. Vantage lab" |
| Stale (>60 s) | grey figures, "figures 3 min old: engine not reporting" on the group header; totals not shown as current |
| Money unknown | per field "£ —" with "(no rate)" once per group, never "not known" on every row |
| Halted / paused | the existing SafetyStrip only (A13: no second banner on this page); group header gets "paused at −8%" in words |

- Filters (bottom sheet on phone, left column on desktop): period (Today / 7 days / 30 days / custom), account,

  Cost probe, Shadow), exit reason, evidence (counted / excluded / censored). Defaults: Today, all accounts, kinds

- Totals line uses the same rows as the list (server-computed, after costs); when the filter holds unread arms the
  line shows count, costs and lab-level money only (§2.5).

### 3.6 Real money: one-click confirmation in this flow

- A pending real proposal is pinned at the top of **Now** and of **Home**, and opens the existing approval card
  (docs/ux/approval-card.md, ui-91-92) with these fixes: line 1 is "REAL · Live (ICM) · 58 s" (account and money class

- After Approve: the card collapses to a fixed-height row "Approved 08:41 · sent to the engine" and the trade appears
  in Now with kind Real within one poll; a refusal at approval shows the RiskGate reason in words, in place.
- Demo entries are never in this flow (ADR 0036).

### 3.7 Accessibility and layout (applies to all of §3)

- Contrast from tokens (AA in light and dark). Side = arrow + word; result = sign + number; kind = word badge; band
  = word. No meaning by colour alone. Short is blue, never red; red only for halt, cap hit, refused.
- 44 px targets (rows, chips, filter buttons, Load more); focus ring on all; rows are buttons with an accessible name
  ("Box break 15m, long, plus £2.10, closed at target").
- Every number has a unit and every time a zone (`TimeText`). The phone never scrolls sideways: tables become cards
  under 720 px (`DataTable mobile="cards"`).

## 4. Telegram at 500+ trades a day

Principle: **push only what changes money at risk on a real account or what stops trading; everything else is a
digest or a pull.** A message per demo fill is 500+ pings a day; the owner would mute the bot and miss the one that
matters.

| Event | Today | New policy |
|---|---|---|
| Real-money proposal | push with buttons | unchanged (sound) |
| Real-money fill / close | none | **push, silent**: "REAL Live (ICM) · LONG 0.05 closed at target +£12.30 (+1.5 R) · 41 min" (one line + deep link) |
| Halt, −8% pause, kill switch, cap hit | push | unchanged (sound) |
| Arm retired at its stop / arm read verdict | daily report | **push, silent**, one line, at most once per arm |
| Order not confirmed / not placed | push | unchanged |
